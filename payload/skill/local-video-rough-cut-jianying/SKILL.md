# 本地视频粗剪并生成剪映草稿

当用户发送类似下面的请求时使用本 Skill：

`帮我粗剪视频，视频素材和台本文件我放到了##`

其中 `##` 是实际本地目录路径。任务完成后必须向用户明确回复：`已经粗剪完毕，可以精剪`。

## 工作边界

### 输入前提

用户提供的目录默认是已经整理过的干净素材目录，目录中的视频均为有效素材。台本是粗剪方向和段落顺序参考，不是逐字字幕稿，也不是删除素材的依据。

目录中的视频不得因为以下原因被删除、跳过或排除：

- 台本没有逐字写出对应内容；
- 实际台词与台本存在口语化表达、同义改写、漏字或补充词；
- 某段内容在台本中描述得不完整，但与整体拍摄主题一致；
- 文件名、拍摄顺序或视频长度不符合预期。

以下情况可以从最终视频轨排除素材：

- 视频文件无法读取或损坏；
- 视频完全黑屏、完全无有效画面或无法恢复；
- 用户明确标记为废片、错误录制或要求排除；
- 视频内容与本次剪辑主题无关，例如摄影师或导演指令、现场沟通、等待、试拍、打板、设备调试、拍摄口令或其他幕后声音；
- 用户在本次任务中明确授权删除某类内容。

与剪辑主题无关的现场片段可以删除，但必须基于实际音频、画面或明确上下文判断，不能仅凭台本没有逐字覆盖就删除。与主题相关的实际拍摄内容，即使台本没有完整写出，也必须保留。

如果素材存在疑似问题但无法确认是否与主题无关，必须保留素材，并在结果中记录疑问。

### agent 的职责

agent 只负责：

1. 读取并检查用户提供目录；
2. 识别视频和台本；
3. 对视频进行实际台词转写；
4. 根据台本方向判断段落关系和排序；
5. 按正确顺序拼接有效素材；
6. 删除有明确证据支持的无效长停顿或气口；
7. 根据实际台词生成可编辑文字轨；
8. 生成并校验剪映草稿。

agent 不负责：

- 擅自筛选用户已经整理好的干净素材，但可以删除明确识别出的、与剪辑主题无关的现场指令或幕后片段；
- 因台本没有覆盖某段内容而删除该段实际拍摄内容；
- 用台本文字替换实际口播文字；
- 擅自删除完整句子、重排句内内容或改写台词；
- 仅凭文件名、目录顺序或视频时长判定素材无效；
- 使用视觉大模型对每个视频逐帧判断是否应该保留，除非用户另有要求或文本信息无法完成排序。

## 工作流程

### 1. 读取和检查输入

从用户消息中提取 `##` 后面的目录路径。保留 Windows 路径中的中文、空格和括号，不要把占位符本身当成路径。

检查目录是否存在，并列出视频与台本文件。视频通常是 `.mp4`、`.mov`、`.m4v`、`.mkv`；台本通常是 `.srt`、`.txt`、`.docx`、`.md`。

以下情况必须停止并向用户说明缺少的信息：

- 目录不存在；
- 目录中没有视频；
- 目录中没有台本；
- 存在多个台本且无法判断主台本。

目录正常时，不因素材数量多、台词不完全匹配或素材排序不明确而中止。

### 2. 检查素材覆盖范围

使用 `ffprobe` 或当前环境中可用的视频信息工具检查每个视频是否可读取、是否包含有效视频流和音频流，并记录时长、分辨率和帧率。

生成素材清单。除明确损坏、无法读取或用户明确排除的文件外，所有输入视频都必须进入后续排序计划。不得生成一个只使用部分输入素材的草稿而不说明原因。

建议在工作目录保存：

- `media_manifest.json`：输入素材清单和可读取状态；
- `source_coverage.json`：每个输入视频最终是否进入时间轴及原因。

### 3. 获取实际台词

使用当前环境中可用的本地 ASR、`whisper.cpp`、`faster-whisper` 或其他本地语音识别工具，对每个有效视频生成带时间码的实际口播转写。

优先使用低算力本地方案。除非用户明确要求，不调用云端 ASR，不使用视频视觉大模型逐帧分析。

ASR 结果至少应保留：

- 原始视频文件；
- 原始开始时间；
- 原始结束时间；
- 实际转写文字；
- 识别置信度或不确定性（工具支持时）。

建议在工作目录保存：

- 每个视频的 `.json` 转写结果；
- 每个视频的 `.srt` 或等效字幕结果。

ASR 结果用于实际台词、时间轴和文字轨。台本不能覆盖 ASR 得到的实际台词。

### 4. 使用台本确定排序，不使用台本删片

对台本和 ASR 结果进行文本标准化和顺序匹配。可以使用关键词重合、编辑距离、句子顺序和轻量语义相似度；不需要为了普通素材排序调用大语言模型或视觉模型。

台本与实际台词不要求逐字一致。允许：

- 口语化表达；
- 同义改写；
- 语气词增减；
- 少量漏字和补充词；
- 台本概括而实际口播更完整。

当实际拍摄内容与台本主题和语义基本一致时，保留实际视频内容，并根据台本方向确定段落顺序。低匹配置信度只能作为审计警告，不能作为删除素材的理由。

建议生成：

- `edit_plan.json`：视频片段、原始时间范围、排序位置、台本段落和匹配信息；
- `matching_report.json`：匹配结果、不确定性和警告。

`edit_plan.json` 中除明确损坏或用户明确排除的文件外，所有输入视频都必须有对应的使用记录。若存在未覆盖文件，生成草稿前必须报错或明确记录原因。

### 5. 只进行必要的气口处理

完成素材排序和拼接计划后，再进行气口检测。气口处理只允许删除有明确证据支持的无效长停顿，例如明显的空白等待、重复起句前的无效停顿或用户明确要求删除的停顿。

必须保留：

- 必要的句间停顿；
- 自然表达节奏；
- 强调停顿；
- 与语义相关的停顿；
- 无法确定是否应删除的停顿。

不能因为台本没有对应文字而删除实际内容，也不能把整句内容、补充说明或完整表达当作气口删除。

### 6. 建立统一时间轴映射

根据最终保留区间建立原始时间轴到粗剪时间轴的映射。视频、音频和文字轨必须使用同一组保留区间和同一套时间映射。

如果删除了停顿：

- 视频片段起止时间必须按映射更新；
- 音频必须与视频保持同步；
- ASR 文字片段必须重新计算开始和结束时间；
- 落在删除区间中的文字必须同步裁切或移动；
- 不得使用未经映射的原始字幕直接放入最终草稿。

### 7. 生成实际台词文字轨

最终文字轨必须基于视频中的实际口播内容生成，优先使用 ASR 转写结果，并根据粗剪后的时间轴重新计算字幕时间。

台本只用于：

- 确定段落和排序；
- 辅助校对 ASR；
- 发现明显漏识别或匹配异常。

台本不能用于：

- 直接替换实际台词；
- 强制改写实际口播；
- 删除台本未覆盖的实际内容；
- 生成与视频声音不一致的字幕。

如果 ASR 结果存在明显错误，应在不改变实际含义和口播顺序的前提下进行必要校正，并记录修正；无法确定时保留实际转写并记录警告，不擅自套用台本。

#### 字幕：「说什么」按实际口播，「怎么显示」按 spec

文字轨「说什么」由上面几条决定；「怎么显示」（字号、颜色、描边、位置、每行字数、单条时长、**语义对比**、入场动画）一律按 `references\subtitle-presentation-spec.md`（v2，由 15 个剪映工程 / 550 条文本片段反推）执行，**不要临场定样式**。七条底线：

| 项 | 取值 |
|---|---|
| 字体 / 字号 | 字语云黑宋 / **11**（±1，全片恒定） |
| 字色 | #FFFFFF；只有强调才换色，**一屏最多 1 个强调色** |
| 描边 / 阴影 / 行距 | 0.08 / 开启、距离 5 / 0.02 |
| 位置 | X=0，Y=**-0.34**（人物访谈类 **-0.43**） |
| 排版 | **单行**；每条 7–12 字（下限 4，硬上限 15，超 15 必须拆句） |
| 时长 / 语速 | 每条 1.2–1.8 s（最短 0.8 s）/ ≤5 字/秒 |
| 层级 | `render_index` ≥ 14000 |

**动画**：全片统一「渐显」0.25 s 入场，出场不加，动画时长 ≤ 片段时长 × 0.4，整片只用这一种入场动画。分类卡里的「主字幕硬切（0 动画）」**不作为扣减项**——除非用户在当次任务中明确要求硬切；两者冲突时以本条为准，并在结果里说明。

**语义对比（必做，不是可选）**：全片同一字号、同一颜色的字幕视为不达标。必须按 spec §4 给关键语义换色 + 放大（同向叠加），并且只能用下表里的颜色与倍率，不得自创：

| 语义 | 颜色 | 字号 | 建议 |
|---|---|---|---|
| 时间节点 / 截止（倒计时、年份、日期） | 暖黄 `#FFF589` | 11 × 1.5–1.7 | 优先独占一行 |
| 利益点 / 结论（判断句、卖点） | 亮黄 `#FFDE00` | 11 × 1.2–1.5 | 行内或独占一行 |
| 品牌 / 地点 / 环节标签 | 青绿 `#59BAC9` / 米黄 `#FDF6C9` | 11 × 1.2–1.3 | 行内或独占一行 |
| 编号 / 清单序号 | 橙 `#FFBF17` | 11 × 3（35 号） | 独占一行 |

- **一屏最多 1 个强调色**：同一条字幕内不得出现 2 种非白色；**同一语义全片只用一个颜色**；强调段同时加粗。
- **放大后单条宽度不得超过「12 字 × 11 号」**（= 132 个字号单位）。超了会折成 2 行、违反单行底线——要拆句，**不要压小字号**。
- 情绪 / 祝福段落不要整段上色，也不要使用暗红 `#B71C1C`（那是质疑色）。

**实现方式**：本 skill 只允许 2 条轨、没有花字轨，所以语义对比必须用**行内分段样式**实现——把文本素材 `content` 里的 `styles` 按字符区间拆成多段（每段 `range: [a, b]`，首尾相接覆盖全文），强调段单独给 `fill.color`、`size`、`bold: true`。**不得为强调新建轨道。**

**分类卡只影响两件事**：按台本把片子归入 ①活动通知 ②工厂实力 ③人物访谈 ④老板观点 ⑤干货教学 ⑥节日情感 之一（分类库在 `E:\字幕规范提取\全部草稿台本\分类台本\`），差异只体现在 Y 位置与节奏上（③ 人物访谈 Y=-0.43，其余 -0.34）。**分类卡不得用来取消上面的动画底线或语义对比。**

例外只有两种：用户当次明确指定了样式，或本次片子不属于上述 6 类。两种情况都要在结果里写明偏离了哪一条。

### 8. 生成剪映草稿

使用当前环境中可用的剪映草稿生成工具，例如 `pyJianYingDraft` 或已经验证过的本地草稿生成脚本。

最终草稿严格只创建两条轨道：

- 1 条 `video` 视频轨；
- 1 条 `text` 文本轨。

不得创建第二条视频轨、音频轨、贴纸轨、特效轨或备选素材轨。

视频轨包含按台本方向排序、完成必要气口处理的全部有效视频素材。文本轨包含根据实际口播生成、并完成时间轴重映射的可编辑文字。

**文字素材的折行和字号必须后处理，库不会替你做对：**

- `pyJianYingDraft` 导出的文本素材 `force_apply_line_max_width` 恒为 `false`，不补一刀就会横向溢出画布。生成后立刻改 JSON：每条文本素材 `force_apply_line_max_width = true`、`line_max_width = 0.82`、`line_feed = 1`。
- 规范里的字号 `11` 是剪映的 `size` 值，不是像素。首次在新画布上出片时用一帧反算系数：`k = 单字实际宽(px) ÷ 画布宽 ÷ 11`。如果 11 号塞不下 7–12 字，改 `size`（或给文字加 `scale`），**不要改字数规则**——字数规则来自规范，字号只是呈现手段。
- 语义对比同样必须后处理：库只会导出「整条一个样式」，强调段要靠拆 `content.styles` 的 `range` 才能实现（见第 7 步），生成后当场合规检查一遍，别等交付时才发现全片一字号。

**文字轨必须是剪映的「字幕」，不是「文本」——否则用户拿不到字幕面板：**

剪映按文本素材的 `type` 决定选中时给哪个面板：`type="text"` 只给「文本」面板（基础/气泡/花字 + 单个样式），`type="subtitle"` 才给图一那种「字幕」面板（字幕 1..N 列表 + 搜索 + 朗读 + 数字人 + 整体样式修改）。`pyJianYingDraft` 的 `TextStyle(auto_wrapping=True)` 会把素材写成 `type="subtitle"`，但**还不够**：剪映自己「识别字幕」的素材还带 `add_type=1`、`group_id="Auto_<ms>"`（同组素材在面板里排成一条列表）、`recognize_text`、`words`（逐字时间）。

统一走 `scripts\subtitle_module.py`，不要手写这些字段：

```python
import sys; sys.path.insert(0, r"C:\Users\lr286\.agents\skills\local-video-rough-cut-jianying\scripts")
from subtitle_module import SUBTITLE_TRACK, promote_draft_to_subtitles, subtitle_style

script.append_tracks([draft.TrackSpec(draft.TrackType.video, "视频"),
                      draft.TrackSpec(draft.TrackType.text, SUBTITLE_TRACK)])
style = subtitle_style(size=11, align=1, max_line_width=0.82)   # 内部 auto_wrapping=True
...
script.save()
promote_draft_to_subtitles(draft_dir)      # 必做：补齐字幕组字段 + 自动换行，返回报告
```

`promote_draft_to_subtitles` 只改明文草稿；剪映打开过的草稿是密文，改不了，只能重新生成。跑完用 `python subtitle_module.py <草稿目录> --verify` 自查，`ok` 必须为 `True`。细节见 `references\jianying-subtitle-module.md`。

### 9. 命名和保存

草稿名称不强制使用客户端当日日期。默认应生成不会与已有草稿重复的唯一名称，避免覆盖或替换已有文件。

命名优先级如下：

1. 用户明确指定草稿名称时，使用用户指定名称；
2. 用户未指定名称时，使用任务主题、素材目录名或其他能识别任务的名称；
3. 如果目标目录中已经存在同名草稿，在名称后追加递增序号或时间标识，例如 `主题_01`、`主题_02`，不得直接覆盖已有草稿。

最终目录为：

`<草稿根目录>\<唯一草稿名称>`（草稿根目录见 `references\env-and-pitfalls.md` 第 1 节路径表，本机为 `E:\草稿\JianyingPro Drafts`）

生成前必须检查目标目录是否已存在。未经用户明确授权，不得删除、覆盖、替换或清空已有草稿目录。生成后应记录实际使用的草稿名称和绝对路径。

### 10. 生成后校验

生成后必须检查：

- `draft_content.json` 存在；
- `draft_meta_info.json` 存在；
- 轨道总数严格为 2；
- 存在且只有 1 条 `video` 轨；
- 存在且只有 1 条 `text` 轨；
- 所有与剪辑主题相关且允许进入的输入视频都在视频轨中有使用记录；
- 视频片段按计划顺序排列；
- 文字轨文字来自实际台词转写；
- **文字轨是「字幕」不是「文本」**：每条文本素材 `type="subtitle"`、`add_type=1`、`group_id` 全片同一个 `Auto_<ms>`、带 `recognize_text` 和 `words`；用 `python scripts\subtitle_module.py <草稿目录> --verify` 复验，`ok` 必须为 `True`；
- 视频片段、文字片段的时间范围有效；
- 视频和文字轨没有明显重叠、倒序或超出总时长的片段；
- `source_coverage.json` 与草稿实际片段一致。

**字幕必须逐条按 spec §9「出片前 QC」检查，不许自己另发明检查项**（这项最容易漏，漏了就等于没做）：

- [ ] 全片只有一档正文字号（强调段除外），字体统一；
- [ ] 没有 >15 字未拆句的条；
- [ ] 没有 1–3 字碎片条；
- [ ] **每条字幕内最多 1 个强调色，且强调色来自 spec §4 的调色板**；
- [ ] **同一语义全片颜色一致**（时间/结论/品牌地点/编号各自一色）；
- [ ] **确有语义对比**——不是全片一字号一颜色；
- [ ] 强调段 `bold = true`，放大倍率在 1.2–1.7×（编号 3×）；
- [ ] 放大后单条宽度 ≤ 132 个字号单位（不会折成 2 行）；
- [ ] 无 2 行字幕；`line_feed = 1`、`line_max_width = 0.82`、`force_apply_line_max_width = true`；
- [ ] **整片入场动画只有 1 种（渐显），无出场动画，动画时长 ≤ 片段时长 40%**；
- [ ] `render_index` ≥ 14000。

上面任何一条不过，都不能报告「粗剪完成」——要么修，要么在结果里明确写「本条不达标 + 原因」。

如果有素材没有进入视频轨、文字轨无法反映实际台词，或轨道结构不符合要求，不能报告粗剪完成，必须先修正或明确报告失败原因。

保存成功不等于剪映已打开。只能报告草稿已生成，不能声称已经在剪映中目检。除非实际打开剪映并完成检查，否则必须说明尚未完成剪映界面验证。

## 工具职责拆解

### Skill 层

Skill 负责定义：

- 输入前提；
- 不得擅自删片的边界；
- 台本与实际台词的关系；
- 排序、拼接和气口处理顺序；
- 实际台词文字轨要求；
- 草稿轨道结构；
- 生成后的验收条件。

### 工具层

工具负责执行：

- `ffprobe`：读取视频流、时长、分辨率和帧率；
- 本地 ASR：生成实际台词和原始时间码；
- Python 文本匹配：比较台本和实际台词并生成排序计划；
- VAD 或音频规则：辅助识别无效长停顿；
- `ffmpeg`：按照计划裁切、拼接和处理时间轴；
- 剪映草稿生成工具：写入视频轨和实际台词文字轨；
- Python 校验脚本：检查素材覆盖、轨道数量、顺序和时间范围。

普通素材排序不应默认调用大语言模型或视觉大模型。只有文本匹配无法判断、素材本身存在明显视觉歧义，且用户确实需要视觉判断时，才可增加视觉分析工具，并记录其作用范围。

## 完成回复

完成时必须回复：

`已经粗剪完毕，可以精剪`

并附：

- 草稿名称；
- 草稿绝对路径；
- 实际使用的视频素材数量；
- 被排除的素材及明确原因（如果有）；
- 气口处理结果；
- 视频轨和文本轨情况；
- 台本与实际台词的匹配警告（如果有）；
- 是否完成剪映界面验证。

如果存在匹配不确定性但素材仍已按规则保留，可以完成流程并在结果中简要说明；如果违反素材覆盖、实际台词文字轨或两轨结构要求，则不能声称已经粗剪完成。

## 关键边界

- 只处理用户提供目录中的素材，不主动扫描或修改其他项目文件。
- 用户明确要求生成剪映草稿时，可以写入目标草稿目录；未经用户明确授权，不得删除、覆盖、替换或清空已有草稿。
- 不输出密钥、Token、环境变量值或其他敏感凭证。
- 台本用于排序和匹配，不用于擅自删除有效素材或替换实际台词。
- 除明确损坏、用户明确排除或用户另行授权的情况外，必须保留用户提供的全部有效视频素材。
- 文字轨必须以实际口播为准，并使用统一时间轴映射。
- 文字轨的素材必须是 `type="subtitle"` 的「字幕」，且带 `add_type/group_id/recognize_text/words`；做成 `type="text"` 的普通文本，用户就没有字幕列表和整体样式修改面板，视为未完成。
- 字幕外观不满足第 10 步的 spec §9 QC 清单（尤其是**语义对比**与**渐显动画**两条），不得报告「粗剪完成」。
- 不把“草稿文件生成成功”表述成“剪映打开验证成功”。
